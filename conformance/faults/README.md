# 套件 C：故障

对一个已经起来、灌好种子的业务链格注入故障，检查业务结果是否正确，并记下每次用了多久。故障全部从组件外部注入，组件里不加故障钩子。注入的办法在 `cells/faults.py`，一句话说明如下：

| 要的故障 | 怎样注入 |
| --- | --- |
| 进程崩溃 | 在容器里给主进程发 SIGABRT（Go 运行时立即中止、退出码 2）。Docker、Podman 照重启策略拉起，Kubernetes 由 kubelet 拉起。不用 `docker kill`：Docker 把它当作手动停止，不会再拉起 |
| 在一步的中间崩溃 | 在格的库里装一个触发器，只有测试自己那张订单会碰到它；它在协调者的事务提交之前 `pg_sleep`，这时参与方已经提交了自己那一半。测试趁这时让进程崩溃，结束卡住的连接（事务回滚），再删掉触发器 |
| 依赖中断 | 停、起基础资源（`be-nats`、`be-postgres`）；停、起授权组件的进程（在外壳里时整个外壳） |

| 测试 | 协议的独立预期 | 恢复后要看到的 |
| --- | --- | --- |
| `test_rs06_…` | RS06：全部确认占用后、本地提交前崩溃 | 订单确认一次，库存、信用各一份占用 |
| `test_rs05_…` | RS05：全部暂存后崩溃，停得超过暂存期限（5 分钟） | 订单未确认，原因 `processing_timeout`，两边都没有占用 |
| `test_bl04_…` | BL04：账单已开具、向来源正式化之前崩溃 | 正式化续上，账单开具一次，订单完成 |
| `test_a_process_crashes_under_load` | R1：销售、库存、出账各在任意时刻崩溃一次 | 进程自己回来；之后的不变量成立 |
| `test_rs18_…` | RS18：消息系统停 2 分钟时确认订单 | 确认照常；恢复后发件表清空（不变量） |
| `test_authorization_goes_away` | 安全 03：授权组件停 | 记下写操作还能放行多久、何时被拒、恢复后多久放行 |
| `test_the_database_restarts` | 数据库重启 | 记下多久恢复应答 |

每个测试把计时追加到 `BE_ACC_FAULT_LOG`（一行一个 JSON）。整个格的不变量（`python -m cells invariants <格> <文件> [等待秒数]`）由运行器在每次故障之后检查：确认过程都走到终态、订单与参与方的分支一致、库存与信用的占用对得上分支、账单与来源的认领一致、发件表发完、没有死掉的后台任务。

## 运行

一次只跑一个（`-k`）：它们会让进程崩溃、停掉基础资源。环境与 L3 场景相同，另需 `BE_ACC_PG_ADMIN`（装、删触发器，读不变量）：

```sh
BE_ACC_CELL=<格的目录> BE_ACC_IAM_TEST_PASSWORD=<测试账号的密码> BE_ACC_PG_ADMIN=<管理员连接> \
  BE_ACC_FAULT_LOG=<文件> uv run pytest -q faults -k rs06
```

不跑本机进程的格（L、LD、LP 行）：BrickKit 的 `mode: local` 不重启进程。装配项目的运行器（`dev/rebuild/experiment-scripts/runner11.sh`）在背景负载下按顺序跑完全部故障。
